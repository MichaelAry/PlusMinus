# План реализации редактора графиков в PlusMinus Studio 4

Исполнитель — Sol 6.2 Low. Рабочая директория — корень PlusMinusM. Результат — встроенное окно Plot Editor, в котором редактирование формулы, параметра или точки обновляет видимый график. Текущая задача охватывает Qt Studio 4. Перенос в Studio 5 и получение потока данных из запущенной программы имеют отдельные критерии и идут после этой версии.

## Сценарий приёмки

Пользователь открывает View → Plot Editor рядом с исходником. В новом документе уже видна кривая sin(x). Пользователь заменяет формулу на a*sin(x), двигает ползунок a, добавляет серию с точками (0, 0), (1, 0.84), (2, 0.91) и сравнивает точки с кривой. Затем увеличивает область около x = 1, открепляет окно, сохраняет файл experiment.pmplot и открывает его снова. Формула, параметр, точки, цвета и границы осей восстанавливаются. Все подписи интерфейса — на английском, как в существующей оболочке. Во время ввода F5 и запуск C++ runner для предпросмотра не требуются.

## Где работать

| Файл | Что использовать |
|---|---|
| `ide/research_shell.py` | Фабрика `_dock`, `build_research_shell`, палитра команд и `ResearchController.open_path`. Новая панель получает постоянный objectName до восстановления раскладки. |
| `ide/studio_qt.py` | `Studio.open_file`, `save_active`, `restore_session`, `closeEvent`. Существующий `Plot.set_series` принимает последовательность Y и размещает отсчёты равномерно по X. Профайлер и история зависят от этого поведения. |
| `src/compiler/expressions.cpp`, `src/compiler/scanner.cpp`, `src/vm/builtins.cpp` | Эталон для синтаксиса чисел, приоритета знака и степени, арности sin, cos, pow. |
| `tools/smoke_qt.py`, `.github/workflows/desktop.yml` | Образцы запуска QApplication, проверки рабочих областей, сборки runner и проверок без дисплея. |

Новые модули предлагается разделить по трём проверяемым границам. В `ide/plot_model.py` разместить документ, работу с координатами и файловым форматом. В `ide/plot_expression.py` — разбор формулы и выборку точек. В `ide/plot_editor.py` — панель, холст и управление обновлениями. Первые два модуля должны импортироваться в стандартном Python 3.9 без Qt. Для рисования достаточно QPainter из уже установленного PySide6-Essentials.

## Шаг 1. Зафиксировать модель и пример документа

Один открытый документ содержит упорядоченный список серий и общую область просмотра. Два типа серий — формула и таблица точек. У каждой серии собственные ID, подпись, цвет и видимость. Значение параметра принадлежит серии, поэтому две формулы могут использовать разные значения a. Во время обычной правки ID сохраняется.

Пример минимального файла версии 1, который следует использовать как вход для теста чтения:

```json
{
  "version": 1,
  "viewport": {"xmin": -10, "xmax": 10, "ymin": -2, "ymax": 2},
  "series": [
    {"id": "wave", "kind": "formula", "label": "Wave", "visible": true,
     "color": "#5AB0FF", "expression": "a*sin(x)", "parameters": {"a": 1}},
    {"id": "samples", "kind": "points", "label": "Measurements", "visible": true,
     "color": "#F2AF57", "points": [[0, 0], [1, 0.84], [2, 0.91]]}
  ]
}
```

Сохранять только исходные данные и viewport. Геометрия дока принадлежит QSettings. Кэш разбора, выборки, сообщения об ошибке и выделенная строка существуют в памяти. У нового документа стартовая область как в примере и одна серия sin(x). Пустой список серий допустим. Концы диапазонов и их разности должны быть конечными, минимумы строго меньше максимумов.

**Готово**, когда тесты создают документ, различают обе разновидности серий, проверяют корректный viewport и независимость параметров двух формул.

## Шаг 2. Реализовать ограниченный язык формул

Поле с подписью «y =» принимает правую часть выражения. Поддержать десятичные числа с ведущей цифрой, переменную x, параметры a, b, c, скобки, унарные знаки, бинарные +, -, *, /, ^, функции sin(x), cos(x), pow(x,y). Тригонометрические аргументы измеряются в радианах. Параметры по умолчанию равны 1. Для MVP допустимы значения от −10 до 10 с шагом 0.01. Указать эти правила в подсказке поля.

Разбирать выражение один раз в дерево либо последовательность операций и переиспользовать при подстановке чисел. Вычислитель принимает только перечисленные операции и имена. Не передавать пользовательский текст в Python eval/exec. Диагностика содержит сообщение и позицию в исходной строке. При неверной арности, лишнем токене и незакрытой скобке возвращать ошибку всей формулы. Деление на ноль, переполнение и отсутствие действительного значения при конкретном x дают пропуск только в этой точке. Ввести проверяемые пределы размера выражения и глубины разбора, например 512 символов и 32 уровня вложенности, включая цепочки унарных знаков и степеней.

**Проверка:** `-2^2 → -4`, `(-2)^2 → 4`, `2^3^2 → 512`, `2^-2 → 0.25`, `sin(0) → 0`. Отдельно проверить `sin(`, `sin(1,2)`, `2x`, неизвестное имя, слишком глубокое выражение и `1/x` при x = 0. После ошибки следующий корректный ввод работает.

## Шаг 3. Построить первую кривую в рабочей IDE

Создать PlotCanvas и PlotEditor. Сначала достаточно одного QLineEdit, начальной формулы, осей с числовыми подписями и линии sin(x). Переиспользовать цвета темы. Область данных ограничить внутренним прямоугольником с местом под подписи. Преобразования координат графика в экранные и обратно должны учитывать направленную вниз экранную ось Y. В paintEvent рисовать готовые сегменты; разбор формулы и выборка выполняются до перерисовки.

В `build_research_shell` зарегистрировать закрываемый и открепляемый док через `_dock`. При первом запуске он скрыт. Добавить действие в меню View через toggleViewAction и команду в палитру, которая показывает док, поднимает его и переводит фокус на формулу. Повторное открытие активирует тот же экземпляр. Закрытие крестиком скрывает панель вместе с текущим черновиком в памяти. Сохранить нумерацию девяти рабочих страниц, которой пользуются навигация и тесты.

**Готово**, когда в обычном окне Studio можно открыть панель, увидеть sin(x), заменить её на x^2, открепить, скрыть и открыть снова с тем же текстом. Преобразование координат проходит тест прямого и обратного отображения углов и центра.

## Шаг 4. Сделать обновления предсказуемыми при быстром вводе

1. На каждую правку сразу увеличивать номер ревизии. На ввод текста поставить однократный QTimer примерно на 60 мс. Движение ползунка и навигацию объединять до одного запроса за кадр или за 16–32 мс. Изменение размера учитывает фактическую ширину области данных.
2. Передавать вычислителю снимок видимых формул, параметров, диапазонов и размера. Выбирать примерно одну точку на логический пиксель ширины, с пределами 256–2048 основных отсчётов на серию. Для смены только цвета использовать готовую выборку.
3. Держать максимум одну вычисляемую задачу и один ожидающий, всегда самый свежий снимок. Фоновому исполнителю передавать только данные. Доставлять результат сигналом в GUI-поток, сверять ревизию до применения. При закрытии документа или замене модели инвалидировать прежнюю ревизию. Предусмотреть кооперативную отмену между блоками выборки и завершение исполнителя при выходе из Studio.
4. При синтаксической ошибке показывать позицию рядом со строкой. Последнюю корректную кривую этой серии можно оставить приглушённой с отметкой «Last valid preview». У новой ошибочной серии есть только диагностика. Успешные серии продолжают обновляться. При открытии другого документа очистить предыдущие кривые.
5. Разделять линию на сегменты в точках с неопределённым значением. Для возможного разрыва между отсчётами проверять середину интервала по отклонению от линейной интерполяции в экранных координатах. Уточнять подозрительные интервалы с ограниченной глубиной и общим бюджетом проб. При сохраняющемся крупном скачке оставлять разрыв. Это приближённое построение; отдельно проверить крутую непрерывную прямую и полюс между соседними отсчётами.

**Готово**, когда искусственно задержанный ответ для старой формулы не заменяет новый график. Для `1/x` и `1/(x-0.123)` тест проверяет отсутствие сегмента через соответствующий полюс в фиксированном окне. Для `1000*x` проверяется сохранение линии. Закрытие окна во время расчёта проходит без обращения к уничтоженному QWidget.

## Шаг 5. Добавить визуальный редактор серий

Использовать горизонтальный QSplitter. Слева — список серий и редактор выбранной, справа — холст. Команды Add formula, Add points и Remove действуют на документ. В строке списка показать переключатель видимости, имя и образец цвета. Выбор строки не меняет данные. Редактор формулы показывает только используемые параметры. Связать ползунок и числовое поле через единое значение с защитой от повторного сигнала. Пока пользователь временно удаляет параметр из текста, сохранить его последнее значение в рамках серии.

Для точек сделать таблицу X/Y с добавлением и удалением строк. Рисовать маркеры в заданных координатах, разрешать повторяющийся X. Принять строку в модель, когда обе ячейки содержат конечные числа. Пока пользователь вводит вторую ячейку или исправляет первую, оставить текст на месте, выделить ячейку с ошибкой и исключить строку из предпросмотра. При сохранении предложить исправить или удалить незавершённую строку. Ошибочную формулу можно сохранить как текст и продолжить редактировать после открытия.

**Готово**, когда две формулы и таблица видны одновременно, выключение серии сразу убирает её с холста, а правка одной строки сохраняет фокус и положение курсора. Удаление последней серии оставляет оси и доступные команды добавления.

## Шаг 6. Реализовать масштаб, перемещение и Fit

Колесо внутри области данных масштабирует обе оси вокруг точки под курсором. Перетаскивание левой кнопкой сдвигает диапазоны на расстояние, соответствующее перемещению в пикселях. При достижении численного предела сохранить последнюю корректную область. На resize сохранять границы в единицах графика.

У формулы бесконечное множество возможных X, поэтому для Fit зафиксировать правило. Для видимых формул взять базовый интервал X от −10 до 10, расширить его по X видимых таблиц, вычислить формулы на полученном интервале и подобрать Y по конечным значениям с отступом 5%. Если видны только таблицы, взять их границы по обеим осям. Для единственного значения добавить ненулевой запас по обе стороны. При полном отсутствии данных вернуть стартовую область. Колесо и перемещение действуют независимо от Fit.

**Готово**, когда точка под курсором сохраняет координаты после zoom с погрешностью до одного пикселя. Отдельные тесты покрывают одну точку, постоянную функцию, пустой документ, скрытую серию с большим значением и изменение размеров окна.

## Шаг 7. Сохранить документ и подключить обычные команды Studio

- Формат — UTF-8 JSON с расширением .pmplot. Проверять версию, тип серии, уникальность ID, цвет, допустимые параметры, конечность чисел и диапазоны. На чтении установить пределы, например 2 МиБ на файл, 16 серий, 10 000 точек суммарно; те же пределы применять при создании и сохранении, чтобы свой файл можно было открыть. Ошибка должна указывать поле или серию.
- При открытии сначала прочитать и проверить новый документ во временной модели. При успешной проверке согласовать замену изменённого текущего документа через Save / Discard / Cancel. При отмене, повреждённом файле или неудачной записи сохранить текущую модель, путь и признак изменений.
- Записывать через временный файл в том же каталоге с атомарной заменой. В панели добавить New, Open, Save и Save As. Изменения формулы, точек, параметров, видимости, цвета и viewport помечают документ изменённым. Начальный пример, успешное открытие и служебная перерисовка оставляют его чистым.
- Направить .pmplot из общего диалога Open и двойного щелчка в дереве проекта в один обработчик. Для Ctrl+S учитывать фокус внутри панели, включая откреплённую панель. Для кнопки Save в общей шапке запоминать последний документ, с которым работал пользователь, поскольку к моменту нажатия кнопка сама может получить фокус. Проверить переходы между исходником, графиком и notebook. Избегать двух активных обработчиков Ctrl+S для одного окна.
- Встроить подтверждение закрытия документа графиков в Studio.closeEvent до остановки задач. Для обычной сессии сохранять в QSettings путь к последнему сохранённому .pmplot. Отсутствующий файл пропускать, повреждённый — диагностировать без блокировки запуска. Диагностический safe mode соблюдает существующий порядок обхода восстановления и записи настроек.

**Готово**, когда файл проходит цикл сохранить → закрыть Studio → открыть снова. Cancel оставляет введённую формулу на месте. При Ctrl+S из откреплённого окна меняется именно .pmplot. После возврата к исходнику и notebook каждый сохраняется по обычному пути.

## Шаг 8. Проверить интеграцию и измерить задержку

Для модели, разбора и выборки добавить тесты `tools/test_plot_*.py` на unittest. Общий desktop CI на Linux обнаруживает такие файлы до установки Qt, поэтому проверки QWidget поместить в Qt smoke, который запускается уже с PySide6. Для тестов открытия, сохранения и восстановления использовать временный каталог и изолированные настройки. Задержки обработки проверять по сигналам и ревизиям с предельным тайм-аутом.

Команды из корня репозитория для Linux с подготовленной .venv:

```bash
python3 -m unittest discover -s tools -p 'test_plot_*.py'
python3 launch.py --no-install --build-only
python3 -m unittest discover -s tools -p 'test_*.py'
QT_QPA_PLATFORM=offscreen .venv/bin/python tools/smoke_qt.py
QT_QPA_PLATFORM=offscreen .venv/bin/python ide/studio_qt.py --safe-mode --gui-smoke
```

На рабочем столе дополнительно проверить меню, ввод, ползунок, масштаб под курсором, перенос дока и сохранение с клавиатуры в откреплённом окне. Для замера взять три видимые формулы sin(x), cos(x), a*sin(x) и ширину области данных около 1000 пикселей. После прогрева сделать 30 одиночных изменений параметра и 30 завершённых правок формулы. Для каждой серии замеров записать медиану и P95 от последнего события ввода до отрисовки соответствующей ревизии, включая таймер. Ориентир — P95 до 150 мс на указанной тестовой машине. Публиковать измеренное значение с ОС, CPU и версией Python. Абсолютный порог оставить для настольного замера, а в CI детерминированно проверять корректность результата и ограниченность очереди.
